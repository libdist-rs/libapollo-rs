Notes
-----
Latency is end-to-end from client-side submit to client-side commit
observation. With `window=10000` in flight, latency is dominated by
queueing (a tx waits ~`window/throughput` seconds before being batched).
To measure raw commit latency, rerun with `-w 1` or a window smaller
than one block.

Sync HotStuff and Opt Sync gain 3-5x vs the pre-libmempool direct-TLS
path: consensus reactors no longer do per-tx `add_transaction` work,
proposals carry a single `BatchHash` instead of N tx hashes, and
batching runs concurrently with consensus.

Apollo's round/chain-based client-side commit loop regressed
(30k -> 19k @ n=3) because the hash-lookup via the new `tx_hash_map`
serializes with vote processing. Follow-up work.
